# NutriCam (MVP)

NutriCam은 음식 사진을 기반으로 식단을 기록하고 영양 통계를 확인할 수 있는 Streamlit 앱입니다.

> 현재 버전은 **실제 AI 모드(CLIP)** 와 **테스트 모드**를 함께 제공합니다.  
> 실제 AI가 동작하지 않을 때는 테스트 모드임을 화면에서 명확히 표시합니다.

## 1. 주요 기능

- 사용자 기본정보 입력 및 저장
- 카메라 촬영(웹캠) 후 식단 기록
- 음식 인식(실제 AI/테스트 모드 선택)
- 칼로리/탄수화물/단백질/지방 계산(실제 영양 DB 기반)
- 하루 요약 통계
- 최근 7일 칼로리/영양소 그래프(Plotly)
- 목표 칼로리 기반 식단 관리
- 영양 섭취 경향 기반 일반 건강관리 조언

## 2. 프로젝트 구조

```text
app.py                # 메인 Streamlit 앱
database.py           # SQLite 생성/저장/조회
camera.py             # 카메라 입력 및 이미지 저장
food_recognition.py   # 음식 인식 (CLIP 기반 + 테스트 모드)
nutrition.py          # 영양 정보 계산
recommendation.py     # 건강 식단 추천 로직
requirements.txt      # 의존성 목록
README.md             # 프로젝트 설명
data/
  nutricam.db         # 실행 시 자동 생성
  images/             # 촬영 이미지 저장 폴더
```

## 3. 단계별 개발/실행 가이드 (처음부터 끝까지)

### Step 1) 프로젝트 준비

- Python 설치 (권장: 3.10+)
- 프로젝트 폴더로 이동

```powershell
cd C:\뉴트리캠
```

### Step 2) 필수 라이브러리 설치

`requirements.txt` 기준으로 설치합니다.

```powershell
pip install -r requirements.txt
```

### Step 3) 로컬 웹앱 실행

아래 명령어로 실행하면 웹앱이 로컬에서 실행됩니다.

```powershell
streamlit run app.py
```

- 기본 접속 주소: `http://localhost:8501`
- 이 프로젝트는 [.streamlit/config.toml](./.streamlit/config.toml)로 localhost 전용 실행이 설정되어 있습니다.
- PC 카메라는 `st.camera_input`으로 바로 사용 가능합니다.

스마트폰 카메라로 테스트하려면(인터넷 배포 아님, 같은 Wi-Fi의 로컬 네트워크만 사용):

```powershell
streamlit run app.py --server.address 0.0.0.0 --server.port 8501
```

그 다음 스마트폰 브라우저에서 `http://PC_IP주소:8501`로 접속하세요.

### Step 4) 기능 사용 순서

1. `1) 사용자 기본정보`에서 목표/활동량 입력 저장  
2. `2) 음식 촬영/기록`에서 카메라 촬영 또는 이미지 업로드  
3. `음식 인식 실행` 후 인식 실패 시 수동 선택/직접 입력  
4. 섭취량(g) 조절 후 영양정보 확인 및 식단 저장  
5. `3) 통계/추천`에서 일일 합계/주간 그래프/관리 조언 확인

### Step 5) 실행 오류가 날 때 빠른 점검

```powershell
python -m compileall .
streamlit run app.py
```

### 영양 API 사용(권장)

실제 영양성분 조회는 식품의약품안전처 OpenAPI를 사용합니다.

- 발급처: 공공데이터포털 `식품의약품안전처_식품영양성분DB정보`
- 환경변수: `MFDS_API_KEY`
- 또는 앱 사이드바의 `MFDS 영양 API 키` 입력칸 사용

예시(Windows PowerShell):

```powershell
$env:MFDS_API_KEY="발급받은_API_KEY"
streamlit run app.py
```

## 4. 테스트 모드 안내

- 테스트 모드는 실제 모델이 아닌 샘플 로직입니다.
- 테스트 결과에는 `(테스트)` 표시가 붙습니다.
- 영양 데이터가 없으면 임의 수치를 표시하지 않고 안내 메시지를 표시합니다.

## 5. AI 모델/API 비교 및 현재 구현

### 비교

1) CLIP Zero-shot (로컬 모델)
- 장점: API 키 없이 사용 가능, 커스텀 음식 후보군(한식 우선) 분류 가능
- 단점: 초기 모델 다운로드 필요, 한국 음식 정확도는 데이터 의존적

2) 클라우드 비전 API (Google Vision, Azure Vision 등)
- 장점: 운영 편의성, 확장성
- 단점: 비용/API 키 필요, 한식 세부 라벨 제어가 제한적

3) 전용 한식 분류 모델(직접 학습)
- 장점: 정확도 향상 가능
- 단점: 데이터셋/학습 인프라 필요, 초기 개발 비용 큼

### 현재 구현 방식

- **실제 AI 모드**: `openai/clip-vit-base-patch32` 기반 zero-shot 분류
- **우선 지원 음식**: 밥, 김치, 불고기, 제육볶음, 된장찌개, 비빔밥, 라면
- 인식 실패/저신뢰 시: 사용자 수동 선택 또는 직접 입력
- **테스트 모드**: 데모용 샘플 인식 (명확히 표시)

## 8. 테스트 방법

아래 순서로 기능을 점검하세요.

1) 문법/모듈 오류 확인

```powershell
python -m compileall .
```

2) 의존성 확인

```powershell
pip install -r requirements.txt
```

3) 프로그램 실행 확인

```powershell
streamlit run app.py
```

- 접속 주소: `http://localhost:8501`D

4) 카메라/업로드 기능 확인
- `2) 음식 촬영/기록` 메뉴 진입
- `카메라 촬영` 또는 `사진 업로드` 중 하나 선택
- 이미지가 화면에 표시되는지 확인

5) 음식 인식 기능 확인
- 인식 모드를 `실제 AI (CLIP)` 또는 `테스트 모드`로 선택
- `음식 인식 실행` 클릭
- 인식 음식명과 신뢰도 점수 출력 확인
- 실패 시 수동 선택/직접 입력이 동작하는지 확인

6) 영양정보 계산 확인
- 섭취량(g) 슬라이더 변경
- 칼로리/탄수화물/단백질/지방 값이 함께 갱신되는지 확인
- 실제 데이터가 없으면 임의값 대신 안내 메시지가 표시되는지 확인

7) SQLite 저장/조회 확인
- `식단 기록 저장` 클릭
- `3) 통계/추천` 메뉴에서 같은 날짜 기록이 표에 보이는지 확인

8) 통계 그래프 확인(Plotly)
- 최근 7일 칼로리 추이 라인 그래프
- 최근 7일 탄수화물/단백질/지방 그룹 막대 그래프
- 목표 칼로리 설정 시 목표선 표시 확인

9) 목표 기반 조언 확인
- 사용자 기본정보에서 목표(감량/유지/증량), 목표 칼로리 저장
- `통계/추천`에서 목표 대비 진행률 및 조언 문구 변화를 확인
